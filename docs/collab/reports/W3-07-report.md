## Deviations
1. **Severity/stickiness of `pause-over-cap`**: the packet's Changes section says "R-SELF **high, sticky**"; its Tests section says "one R-SELF **medium**" with no stickiness. Implemented **high, sticky** (added to `notify.STICKY_EVENTS`), matching the Changes section, the design spec's categorical R-SELF-is-high convention for the two sibling tamper events, and the packet's own stated rationale ("a mute attempt is loud instead of silent" only holds if it's sticky). The squad's five-way cross-review flagged this as a genuine, unresolved contradiction needing Chief/Owner sign-off before implementation; none was available synchronously, so I made the call and record it here rather than block. **ASK-1**: confirm `pause-over-cap` should be high+sticky, or revert to medium/non-sticky.
2. **Writer coverage beyond `sentinel-action pause`**: the packet's Changes section names only `sentinel-action` announcing its writes. The cross-review's highest-confidence finding (verified live on this machine: `sentinel-inventory.timer` enabled, next run within a day, running `sentinel-scout --refresh` -> `scout.write_watchlist` with no announce path) meant implementing only the letter of the Changes section would produce a real sticky/critical/un-pausable false alarm the day this merges. Wired `scout.write_watchlist` (closes that specific regression) and every `sentinel-action` subcommand that rewrites an operational file (`approve`/`dismiss`/`investigate`/`kill`/`notify`, not just `pause`) into the same announce mechanism, so ordinary user actions do not self-trigger foreign-write alerts either.
3. (see #2 -- combined for brevity)
4. **Self-approval bypass**: `Daemon.emit()`'s `_allow_decision()` gate runs before `append_alert`/notify for every alert, including R-SELF, and `allowlist.fingerprint()` is a public deterministic function -- a same-uid process could pre-silence every future tamper alert with one ordinary allowlist entry, defeating this packet's entire premise. The packet's Changes section never mentions exempting R-SELF from the allow gate; this is a Goal-vs-Changes gap the cross-review found and verified in `daemon.py:507-519`. Fixed by exempting the three tamper-evidence events (`foreign-write`/`alert-log-truncated`/`pause-over-cap`, i.e. `notify.STICKY_EVENTS`) from the allow-decision gate in `emit()`, mirroring how they already bypass pause/prefs/burst in `Notifier.send()`. **ASK-2**: confirm this scope (only the sticky self-defense events, not every R-SELF alert -- e.g. the pre-existing exe-identity R-SELF for a nano edit of `config.toml` still goes through the allow gate as before) is the intended fix.
5. **One pre-existing acceptance test needed a one-line fix, not just the two named-broken tests**: `tests/acceptance/test_blackbox_grok.py::test_sticky_sent_while_paused` pauses via the real CLI (`action_main(["pause","1h"])`, real wall-clock time) but reads it back through the fixture's `Daemon`, whose `wall_clock` is a deterministic clock fixed at a 2023 epoch for unrelated determinism reasons elsewhere in the suite. Once `is_paused()` is cap-aware, that clock mismatch reads as `pause_until - now` spanning years, tripping the new 24h cap and making the test see "not paused". Fixed by setting the fixture's clock to real time at the top of that one test (`isolated.clock.t = time.time()`) rather than touching the shared `Isolated`/`Clock`/`daemon()` fixture used by every other acceptance test. `tests/test_notify.py`/`tests/test_notify_burst.py` also needed their `monkeypatch.setattr("sentinel.notify.is_paused", lambda: False)` widened to `lambda now=None: False`, since `Notifier._is_paused()` now always calls `is_paused(now=...)`.
6. **`StateLedger.check()`'s classification is content-based (size+sha256), not mtime-based**, even though `record()` stores `mtime_ns` per R4's literal spec. `write_private_atomic` rewrites via a fresh inode on every call (mtime always changes) even when content is unchanged, so an mtime-inclusive equality check would misclassify plenty of legitimate idempotent rewrites as foreign. `mtime_ns` is still recorded (available for future investigate.py evidence) but not used to decide `unchanged`/`foreign`/`ours`. Not covered by contradiction in the packet; a design choice, not a correction.
7. **Deletion is out of scope for `check()`**: a currently-missing file (`.stat()` fails) always returns `unchanged` regardless of ledger state, so e.g. `notify --reset` deleting `notify-prefs.json`, or the daemon's own `clear_session()` deleting `allowlist-session.json` at startup, never raises. R11 is specifically about `alerts.jsonl` *shrinking*, not disappearing; a full-file-deletion tripwire was not in scope and is not implemented.
